Source rules: https://cloud.google.com/terms/service-terms section 17; https://workspace.google.com/terms/ai-tools/; https://developers.google.com/workspace/guides/quota-usage-tiers; https://developers.google.com/workspace/guides/view-edit-quotas.
## Policy
The prototype evaluates metadata only. Caller-supplied source tags are NOT trusted provenance; future integration must derive them at a verified ingress, inherit tags and earliest acquisition time on derivatives, and never reset the retention clock by copying or embedding. Unknown sources are denied; any restricted tag dominates independent tags. Cloud customer data requires separate review rather than equating it with Google technical information. The 30-day cap is a conservative upper bound also used for covered Workspace user data here, with earlier active task deadlines; not a universal legal retention allowance. Deny learning, tuning, dataset creation, distillation, competing service development and persistent memory for restricted inputs. No automatic data deletion: revocation and expiry signals only. Production must block reads immediately and support approved deletion across primary stores, caches, indexes, logs, snapshots and backups. Review actual Workspace terms and user-data policies before deployment.
## MCP migration preparation
No live adapter or endpoint invocation included. Future adapter contract: authenticate approved principal, verify Google MCP endpoint/product, account/project and tier with trusted configuration, map permitted operation to provider tool schema, check active task and scopes, estimate conservative provider request units before call, reserve shared quota, call once, reconcile provider metering and classify response at ingress. No REST fallback, automatic retries, new OAuth scopes, or paid-tier switch. On unknown unit cost, missing counter, quota error, uncertain tier or authorization, stop. The prototype only models reservation admission. Default 4,500 units per UTC project/product day is a local conservative margin below published 5,000; verify provider reset timezone, per-minute/user/tool limits, actual multi-call costs, all out-of-band consumption and authoritative tier before deployment. In-memory ledger is neither durable nor distributed; process restart and multiple workers invalidate its guarantees. Use atomic shared persistent metering and reconciliation before any live use.
